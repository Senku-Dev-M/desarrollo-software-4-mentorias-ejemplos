# ProductsSql — Supabase con una tabla creada desde SQL Editor

API mínima ASP.NET Core que utiliza Entity Framework Core y Npgsql para acceder
a una tabla PostgreSQL que **ya fue creada manualmente en Supabase**.

En este proyecto, EF Core no administra el esquema:

```text
Supabase SQL Editor
   ↓
CREATE TABLE public.products_sql
   ↓
ProductsDbContext mapea la tabla existente
   ↓
GET y POST usan EF Core + Npgsql
```

No hay migraciones, `EnsureCreated()` ni `Database.Migrate()`.

## Resultado

El proyecto expone:

| Método | Ruta | Resultado |
|---|---|---|
| `POST` | `/products` | Valida e inserta un producto; devuelve `201 Created` |
| `GET` | `/products` | Devuelve productos ordenados por `id` |

Antes de iniciar la API debe existir:

```text
public.products_sql
├─ id    integer identity, primary key, not null
├─ name  varchar(120), not null
└─ price numeric(10,2), not null
```

## 1. Preparar el proyecto en Supabase

En [Supabase Dashboard](https://supabase.com/dashboard):

1. Crea o abre un proyecto de práctica.
2. Conserva la contraseña PostgreSQL.
3. Espera hasta que la base aparezca disponible.
4. Pulsa **Connect**.
5. Selecciona **Session pooler**.
6. Expande **Connection parameters** y copia host, puerto, base y usuario.

Para Session pooler:

```text
Host:     aws-<INDICE>-<REGION>.pooler.supabase.com
Port:     5432
Database: postgres
Username: postgres.<PROJECT_REF>
```

Session pooler permite conectar la API desde una red IPv4. No crea la tabla: el
script SQL del siguiente paso es el responsable del esquema.

No utilices Transaction pooler en este proyecto. Su puerto habitual es `6543` y
está pensado para cargas serverless de transacciones breves.

## 2. Crear la tabla desde SQL Editor

1. Abre **SQL Editor** en el Dashboard.
2. Pulsa **New query** o `+`.
3. Pega exactamente:

```sql
create table public.products_sql (
    id integer generated by default as identity primary key,
    name varchar(120) not null,
    price numeric(10,2) not null
);

alter table public.products_sql enable row level security;
revoke all on table public.products_sql from anon, authenticated;
```

4. Comprueba que el nombre sea `products_sql`.
5. Pulsa **Run**.
6. Debes ver un resultado equivalente a `Success. No rows returned`.

El script también está disponible en:

```text
../../sql/products.sql
```

### Qué crea el SQL

- `id`: entero con identidad generada por PostgreSQL y clave primaria.
- `name`: texto obligatorio, máximo 120 caracteres.
- `price`: decimal obligatorio, 10 dígitos totales y 2 decimales.
- RLS habilitado.
- Sin permisos para los roles `anon` y `authenticated`.

Desde octubre de 2026, Supabase no expone automáticamente todas las tablas
nuevas a Data API/GraphQL. La exposición a Data API y RLS son controles
diferentes. Este proyecto no necesita Data API: Npgsql conecta a PostgreSQL.

### No ejecutes el script dos veces

Si la tabla ya existe, PostgreSQL devuelve:

```text
relation "products_sql" already exists
```

No borres la tabla automáticamente. Primero verifica si contiene datos.

## 3. Verificar la tabla antes de conectar .NET

En **Table Editor** o **Database → Tables**:

1. abre `public.products_sql`;
2. comprueba las tres columnas;
3. confirma clave primaria e identidad en `id`;
4. comprueba que inicialmente no haya filas.

Verificación SQL:

```sql
select column_name, data_type, character_maximum_length,
       numeric_precision, numeric_scale, is_nullable,
       is_identity, identity_generation
from information_schema.columns
where table_schema = 'public'
  and table_name = 'products_sql'
order by ordinal_position;
```

RLS:

```sql
select relname, relrowsecurity
from pg_class
where oid = 'public.products_sql'::regclass;
```

`relrowsecurity` debe ser `true`.

## 4. Descargar y configurar el certificado SSL

En Supabase:

1. abre **Database**;
2. abre **Settings**;
3. busca **SSL configuration**;
4. pulsa **Download certificate**.

Guarda el certificado en una ruta estable:

```text
C:\Users\TU_USUARIO\.certs\supabase-prod-ca.crt
```

Verifica:

```powershell
Test-Path "$env:USERPROFILE\.certs\supabase-prod-ca.crt"
```

Debe devolver `True`.

La conexión debe incluir:

```text
SSL Mode=VerifyFull;Root Certificate=C:\Users\TU_USUARIO\.certs\supabase-prod-ca.crt
```

`VerifyFull` exige TLS, valida la autoridad certificadora y verifica que el
nombre del host coincida.

## 5. Configurar User Secrets

La aplicación lee:

```text
ConnectionStrings:Supabase
```

Desde la raíz `tutorial-supabase-dotnet`:

```powershell
.\scripts\configurar-conexion.ps1 -Metodo sql
```

Desde esta carpeta:

```powershell
..\..\scripts\configurar-conexion.ps1 -Metodo sql
```

Pega una cadena de una sola línea:

```text
Host=<HOST_DEL_POOLER>;Port=5432;Database=postgres;Username=postgres.<PROJECT_REF>;Password=<CONTRASEÑA>;SSL Mode=VerifyFull;Root Certificate=C:\Users\TU_USUARIO\.certs\supabase-prod-ca.crt
```

No guardes esa cadena en `appsettings.json` ni en un commit.

User Secrets no cifra el archivo; solo lo mantiene fuera del proyecto. En un
entorno desplegado utiliza un gestor de secretos o:

```text
ConnectionStrings__Supabase
```

```text
dotnet ef database update
```

La creación de `products_sql` ocurrió exclusivamente en SQL Editor.

## 8. Qué hace el código

`ProductsDbContext.cs` contiene:

```csharp
product.ToTable("products_sql", "public");
```

Esta línea no crea la tabla. Solo indica a EF Core qué objeto PostgreSQL debe
utilizar.

El resto del mapeo debe coincidir exactamente con el SQL:

```csharp
product.Property(p => p.Id)
    .HasColumnName("id")
    .UseIdentityByDefaultColumn();

product.Property(p => p.Name)
    .HasColumnName("name")
    .HasMaxLength(120)
    .IsRequired();

product.Property(p => p.Price)
    .HasColumnName("price")
    .HasPrecision(10, 2)
    .IsRequired();
```

`Program.cs` obtiene la conexión y registra Npgsql:

```csharp
var connectionString = builder.Configuration
    .GetConnectionString("Supabase");

builder.Services.AddDbContext<ProductsDbContext>(options =>
    options.UseNpgsql(connectionString));
```

Los endpoints utilizan `ProductsDbContext`, pero no modifican el esquema.

### Regla del proyecto

No agregues:

```csharp
db.Database.EnsureCreated();
db.Database.Migrate();
```

Tampoco crees una carpeta `Migrations` para administrar `products_sql`.

## 9. Ejecutar la API

Ejecuta:

```powershell
dotnet run --urls http://localhost:5080
```

La aplicación se conectará a la tabla existente a través de Session pooler.

Si `products_sql` no existe en la base indicada por la conexión, el primer GET o
POST fallará con `relation "products_sql" does not exist`.

## 12. Cambiar la estructura correctamente

Si necesitas agregar `stock`, modifica primero el script versionado:

```sql
alter table public.products_sql
add column stock integer not null default 0;
```

Ejecuta ese cambio en SQL Editor y después actualiza el modelo/mapeo C#:

```csharp
public int Stock { get; set; }
```

```csharp
product.Property(p => p.Stock)
    .HasColumnName("stock")
    .IsRequired();
```

Guarda el SQL en un archivo nuevo y versionado. No dependas únicamente del
historial visual de SQL Editor.

## 13. Errores comunes

### `relation "products_sql" does not exist`

La tabla no fue creada en la base a la que apunta la conexión. Comprueba el
proyecto Supabase y ejecuta `../../sql/products.sql` en su SQL Editor.

### `relation "products_sql" already exists`

El script ya fue ejecutado. No borres la tabla. Verifica estructura y datos.

### `Tenant or user not found`

Para Session pooler el usuario debe ser `postgres.<PROJECT_REF>`. Copia host y
usuario desde **Connect → Session pooler**.

### `password authentication failed`

Usa la contraseña PostgreSQL del proyecto, no la contraseña de tu cuenta
Supabase. Si fue restablecida, actualiza User Secrets.

### Error de certificado

Comprueba la ruta con `Test-Path`, el host exacto y el certificado descargado del
proyecto. No uses `Trust Server Certificate=true` para ocultar el error.

### `permission denied for table products_sql`

Comprueba el usuario de conexión. Este ejemplo usa el usuario PostgreSQL
administrativo. Un rol limitado necesita `GRANT` explícitos.

No concedas acceso público ni desactives RLS para resolver rápidamente el
problema.

### El puerto 5080 está ocupado

Detén `ProductsEf` con `Ctrl+C` antes de iniciar este proyecto, o utiliza:

```powershell
dotnet run --urls http://localhost:5081
```
